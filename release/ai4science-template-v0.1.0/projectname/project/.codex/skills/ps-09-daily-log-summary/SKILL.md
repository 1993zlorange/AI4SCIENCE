# 项目日志日报汇总

## 唯一职责

把一次输入快照中的项目日志按文件名日期分组，形成事实可追溯的中文日报。只读取源日志并新增日报；不修改、移动、删除源日志，不把日报当作验收、科研结论或完成证明。

## 定位项目与输入

1. 从当前工作目录向上查找最近的、包含 `project-supervision` 配置块的根级 `AGENTS.md`。找不到时停止，并请操作者给出项目根；不得根据目录名猜测。
2. 输入目录以操作者显式路径为准。未指定时，将根级配置中的 `project_management_root` 与 `logs_dir` 组合为默认目录。
3. 默认只读输入目录第一层中文本文件，文件 stem 必须以“日志”结尾；支持 `.md`、`.txt`、`.log`、`.json` 和 `.jsonl`。只有操作者明确要求时才递归或改变筛选条件。
4. 在开始读取前记录符合条件的文件清单，形成输入快照。日报生成操作后新增的治理日志不回填到本次快照，避免递归汇总。

路径不存在、不是目录或不可读时停止，不创建替代输入，不回退到其他项目。跳过二进制、损坏或不支持的文件，并在结果中列明原因。

## 日期选择

- 日期只取文件名开头的 `YYYYMMDD-`，并校验为真实日历日期；不得使用创建时间或修改时间补造日期。
- 操作者指定单日、日期范围或“全部日期”时按其要求处理。未指定时只处理当前本地日期。
- 每个目标日期生成一份日报。没有匹配日志时报告“无匹配日志”，不创建空日报。
- 文件缺少合法日期前缀、日期不在目标范围或 stem 不以“日志”结尾时，排除并计入筛选统计。

## 汇总规则

逐份读取快照内文件，区分并合并以下内容：已完成事实、实际产物、验证及结果、变更与影响、问题或阻塞、未执行项、成本时间、下一步和人工决定。

- 只把源日志明确记载的实际动作写入“已完成事项”。计划、目标、建议、推断、待办和未执行项必须保留原状态。
- 重复描述按同一需求、动作或证据合并，保留所有来源；冲突内容并列呈现，不自行裁决。
- 源日志有具体时间时保留到分钟；没有时间时写“源日志未记录具体时间”，不得根据文件时间推断。
- 每项关键结论引用项目相对源文件路径；能稳定定位时附行号。不得复制密钥、令牌、连接串、敏感样本或不必要的绝对路径。
- 日报摘要说明当日主要事实，不以文件数量、模板占位符或未验证计划冒充进展。

## 输出

从 [中文日报模板](assets/20260913-项目日志日报汇总-输出模板.md)开始填写，移除所有未使用占位符。

- 输出目录固定为当前项目的 `<project_management_root>/dailylogs/`；仅在至少有一份有效日报时按需创建。
- 文件名为 `YYYYMMDD-摘要-日报.md`。摘要由操作者提供时优先使用；否则根据当日主要事实生成简短、明确、适合文件名的中文摘要，并去除空格和 `\\/:*?"<>|`。
- 不覆盖同名文件。同名文件已存在时停止该日期的写入，报告冲突路径；只有操作者另行明确授权覆盖或给出不同摘要后才继续。
- frontmatter 和正文中的来源路径使用项目相对路径，不写开发者机器绝对路径。

## 验证

写入后检查：文件名和报告日期一致；来源清单与输入快照一致；全部关键事实可回溯；没有把计划写成完成；没有残留占位符或敏感信息；同名源日志未被修改。项目提供治理校验器时运行其只读检查，并如实记录未执行的检查。

## 权限、幂等与失败边界

默认只允许读取获准日志目录并在当前项目 `dailylogs/` 新增文件。不联网，不提交、推送、发布、删除、移动或覆盖，不读取凭据。

相同输入与相同摘要重复运行时，同名保护使第二次运行不产生新文件。多个操作者可能同时写同一日报时，先重新检查目标是否存在；发现冲突立即停止，不用序号静默绕过。任何输入缺失、日期冲突、来源矛盾、权限不足或校验失败都必须如实报告，已成功生成的其他日期日报可以保留并逐项列明状态。

维护人：项目监理。进化指标：匹配文件数、排除文件数、无证据陈述数、冲突次数、重复执行新增文件数和人工纠正次数。
