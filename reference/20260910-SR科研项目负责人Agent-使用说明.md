> 版本：2026-09-10
>
> 全局 Agent：`sr-research-project-lead`
>
> 依据：[20260909-科研流程-流程说明.md](20260909-科研流程-流程说明.md)、[20260910-SR四Agent科研工作流-交接说明.md](20260910-SR四Agent科研工作流-交接说明.md)
> 配置：`C:\Users\PC\.codex\agents\sr-research-project-lead.toml`

## 0. 与项目交付 Agent 的关系

`sr-research-project-lead` 只编排四个专业 SR Agent。它不会自动调用 `project-manager`、`engineer` 或 `project-test`，也不会把科研结论转写成软件范围。项目需要把研究成果转化为科研工作台功能时，由人确认转化目标后按下列链路单独推进：

```text
SR 成效卡 / 原始证据
  -> 人确认“需要形成软件能力”
  -> project-manager：需求理解契约、PRD/SRS、验收条件
  -> $project-architect-agent：架构、SDD、ADR
  -> engineer：实现与开发验证
  -> project-test：独立功能验收
```

其中项目架构能力目前是全局 `$project-architect-agent` Skill，并没有注册为独立的 `project-architect` Agent。负责人可以在 RPL-03 建议中指出“应进入软件交付链”，但不能越过需求确认或代替项目经理派发软件任务。

## 1. 定位

科研项目负责人是四个专业科研 Agent 之上的证据调度者，负责回答三个问题：

1. 项目实际上完成了什么，证据在哪里？
2. 当前研究的主环节、最后通过的证据门和下一个阻塞点是什么？
3. 下一步最值得投入的一个 P0、最多两个 P1 应交给哪个 Agent 的哪个工作流？

它不直接拥有 SR-01 至 SR-68，不替代首席研究员做 claim，不替代方法构建者建模型，不替代实验员运行实验，也不替代批判性评审员独立审查。

负责人只把八类方面目录中的 `SR-NN-*.md` 识别为合规成效卡，并按 PI-E01 至 CR-P01 的 12 个工作流子目录读取时间戳交接书。旧式 `SR-NN_*.md` 可作为原始证据，但不能直接证明工作包已关闭。

## 2. 四个工作流

| 编号 | 名称 | 何时执行 | 核心输入 | 输出 |
|---|---|---|---|---|
| RPL-01 | 项目成果与交接盘点 | 每次查看项目现状时首先执行 | 八方面目录中的 `SR-NN-*.md`、12 个工作流目录中的时间戳交接书和真实产物 | 成果账本、12 工作流覆盖矩阵、断链/矛盾/缺卡清单 |
| RPL-02 | 研究阶段与证据门诊断 | RPL-01 完成后 | 覆盖矩阵、closure、人工 verdict、原始证据 | 主环节、并行次环节、最后通过 Gate、下一个受阻 Gate、置信度 |
| RPL-03 | 下一步组合与派单计划 | 需要给出推进建议时 | 阶段诊断、关键路径、资源与风险 | 一个 P0、最多两个 P1，以及可直接调用专业 Agent 的 prompt |
| RPL-04 | 交接验收与周期复盘 | 专业 Agent 返回成果后 | 新成效卡、六字段交接书、对应真实产物 | 验收矩阵、阶段变化、保留风险、下一周期建议 |

默认调用执行 RPL-01 → RPL-02 → RPL-03，但只读不派单。只有用户明确说“按建议执行”“调用专业 Agent 推进”时，才允许派发；每次专业 Agent 返回后执行 RPL-04。

## 3. 如何判断当前研究环节

负责人按“最早未通过的关键证据门”判断主环节，而不是根据最新文件名判断。

| 环节 | 必须核查的工作流 | 通过条件 |
|---|---|---|
| Explore 探索 | PI-E01、MB-E01、CR-E01、EX-E01 | 问题、证据、假设、最小证伪与资源边界均有 closure，并有研究设计冻结的人工决定 |
| Execute 执行 | MB-X01、EX-X01、CR-X01、PI-X01 | 实现契约、正式运行、完整性/归因审计、claim 与路线决策均有证据和人工决定 |
| Express 表达 | EX-P01、MB-P01、CR-P01、PI-P01 | 分析图表、方法实验写作、独立内审、最终主张与归档全部证据闭环 |
| Closed 已关闭 | 三个环节均通过 | 阶段包可接续，最终范围和结论已由具名人类验收 |

判定规则：

- 按 [SR 四 Agent 科研工作流与交接说明](20260910-SR四Agent科研工作流-交接说明.md) 的输入矩阵核对每个工作流实际读取的 SR 卡和上游交接书。
- 后期已有论文或图，不能证明前期 Gate 已通过。
- 可以报告一个主环节和若干并行次环节。
- 卡片写 `accepted` 但没有具名人工 verdict 时，按 `partial` 处理。
- 缺卡但存在真实结果时，结论标为 provisional，并派给原主责 Agent 补卡，不重跑已有工作。
- 冲突时优先级为：原始数据/不可变日志/哈希/原文/具名决定，高于汇总报告和聊天总结。
- 文件时间只用于定位版本，不能证明科研完成。

## 4. 可调用的专业 Agent

| 当前问题 | 目标 Agent | 工作流 | 可按需调用的 Skill |
|---|---|---|---|
| 问题模糊、范围漂移、周计划不成立 | `sr-principal-investigator` | PI-E01 | SR-01、02、03、05、59、60、66 |
| 文献证据、假设、创新点、模型蓝图不足 | `sr-method-builder` | MB-E01 | SR-07 至 16、18、21、22、23 |
| 问题有效性或最近邻差异缺少独立挑战 | `sr-critical-reviewer` | CR-E01 | SR-04、06、17、19 |
| 需要最低成本证伪与资源/回退设计 | `sr-experimenter` | EX-E01 | SR-20、28、29 |
| Schema、基线、实现、阻塞或接口不稳定 | `sr-method-builder` | MB-X01 | SR-24 至 27、62、63 |
| 需要真实数据处理和正式实验矩阵 | `sr-experimenter` | EX-X01 | SR-30 至 39 |
| 有结果但完整性、误差或归因存疑 | `sr-critical-reviewer` | CR-X01 | SR-40、44、45、46 |
| 需要证据门、claim、风险或路线决策 | `sr-principal-investigator` | PI-X01 | SR-48、61、64、65、67 |
| 需要统计、切片、案例、机制证据或核心图 | `sr-experimenter` | EX-P01 | SR-41、42、43、47、53 |
| 需要忠实于实现的技术与实验章节 | `sr-method-builder` | MB-P01 | SR-51、52 |
| 稿件需要独立拒稿风险审查 | `sr-critical-reviewer` | CR-P01 | SR-55、56 |
| 需要最终主张、叙事、修订、报告或归档 | `sr-principal-investigator` | PI-P01 | SR-49、50、54、57、58、68 |

负责人不能为了“看起来完整”要求一个工作流调用其全部 Skill，只选择关闭当前未知量真正需要的 Skill。

## 5. 建议如何排序

负责人只给一个 P0、最多两个 P1：

- P0：不解决就不能通过下一个证据门，或可能使当前路线失效的问题。
- P1：可并行准备且不越过 Gate 的高信息价值工作。
- 暂缓：前置证据不足、资源尚未批准、会制造返工或只能改善外观的工作。

排序维度包括关键路径解锁价值、信息增益、证据薄弱程度、科学风险、资源成本和前置条件成熟度。建议中必须分别写清：

- 目标 Agent 与工作流编号；
- 实际需要的叶子 Skill；
- 为什么现在做；
- 已验证输入及其路径；
- 缺失前提；
- 预期产物和完成标准；
- 人工介入点与停止条件；
- 可以直接执行的调用 prompt。

## 6. 标准调用方法

只查看并建议：

```text
调用 sr-research-project-lead，查看 E:\zl\01-Project\AI4CAE3 项目文件夹目前成果，给出下一步工作建议。
```

指定其他项目：

```text
调用 sr-research-project-lead，查看 XXX 项目文件夹目前成果。
请执行 RPL-01、RPL-02、RPL-03，只读检查，不调用其他 Agent。
给出当前研究环节、证据门状态、一个 P0 和最多两个 P1。
```

确认建议后执行：

```text
调用 sr-research-project-lead，按刚才批准的 P0 推进。
只调用建议中指定的专业 Agent 和工作流；
先让专业 Agent 返回 work contract，遇到人工检查点暂停。
```

若用户只说“给出建议”，负责人不能自动调用专业 Agent、启动实验或修改项目文件。

## 8. 人工介入与权限

以下事项负责人只能准备决策材料，不能替人批准：

- 改变研究问题、范围、核心假设或创新性主张；
- 数据纳入/排除、泄漏、许可、隐私和伦理；
- 启动或扩大仿真、实验、流片、采购和共享设备使用；
- 把异常解释为科学现象、删点、选择统计检验或提高 claim；
- 协作者承诺、作者身份、投稿、专利和公开发布。

即使用户批准负责人“推进 P0”，后续出现新的 L2/L3 检查点仍须再次暂停。
