# 科研工作包与 SR Skills 组合方案

> 日期：2026-09-08  
> 依据：`idea/科研工作分解与每周组会汇报模板_20260828.md`  
> 目标：把原文 8 个科研方面、68 个可执行工作包组织为以博士生真实科研流程为主线的 `SR-XX` 分 Skill，并明确传统人工流程、AI 辅助边界和可验收模板。  
> 当前状态：设计稿，不代表第三方 Skill 已安装，也不代表 `SR-XX` 已完成代码实现。

## 1. 为什么上一版没有列入这三个项目

### 1.1 `nature-skills`

上一版采用“literature review、experimental design、statistics、scientific writing”等能力关键词检索，搜索结果被同能力的 K-Dense Skills 占据，没有再用仓库精确名称检索。这一检索策略漏掉了套件级候选，是上一版清单的不完整之处。

精确检索后，`Yuan1z0825/nature-skills` 应进入核心候选：仓库采用 Apache-2.0，GitHub 约 39.9K stars，包含 19 个可触发科研 Skill；单项在 skills.sh 约有 2.5K～12.8K 安装。它不仅覆盖论文写作，还覆盖文献搜索、Paper Card、实验日志、数据可用性、统计审查、科研绘图、预审、审稿回复和组会 PPT。来源：[GitHub](https://github.com/Yuan1z0825/nature-skills)、[skills.sh](https://skills.sh/yuan1z0825/nature-skills/nature-writing)。

它对 SR 设计最有价值的不是“Nature 风格”四个字，而是以下结构：

- 一个 Skill 只处理一个清晰任务，路由器不亲自做实质工作。
- `manifest.yaml` 按任务、论文类型、章节、语言、期刊等轴选择参考资料。
- `nature-shared` 只保存共享定义，不作为独立用户工作流。
- 默认只加载当前任务需要的片段，避免把整套指南一次性塞入上下文。
- 先识别 claim、evidence、boundary，再生成文字、图表或投稿材料。

### 1.2 `academic-research-skills`

上一版检索到了 `academic-paper`，但 GitHub API 将许可证显示为 `NOASSERTION`，因此按“开源可复用”的严格口径没有纳入。人工核验后，仓库实际带有 `CC BY-NC 4.0` 许可证，即允许署名、非商业使用，但带有 NonCommercial 限制，不能等同于 MIT/Apache-2.0 的宽松开源许可。

该项目仍然非常值得作为流程设计参考：GitHub 约 46.8K stars，包含 `deep-research`、`academic-paper`、`academic-paper-reviewer` 和 `academic-pipeline`；后者采用“研究 → 写作 → 完整性检查 → 评审 → 修订 → 复审 → 最终检查 → 定稿”的编排方式。来源：[GitHub](https://github.com/Imbad0202/academic-research-skills)、[skills.sh](https://skills.sh/imbad0202/academic-research-skills/academic-pipeline)。

SR 可以借鉴其编排器、状态机、Material Passport、阶段交接契约和强制完整性门，但不应直接复制受 CC BY-NC 4.0 约束的正文，也不应照搬它面向“论文生产”的全部阶段，因为 SR 的主线是科研认知闭环，而不仅是成稿。

### 1.3 `research-paper-writing`

`research-paper-writing` 是高重名关键词。skills.sh 返回多个实现；本方案将用户所指消歧为 `Master-cai/Research-Paper-Writing-Skills@research-paper-writing`。该仓库采用 MIT，GitHub 约 6.6K stars，skills.sh 约 1.4K 安装。来源：[GitHub](https://github.com/Master-cai/Research-Paper-Writing-Skills)、[skills.sh](https://skills.sh/master-cai/research-paper-writing-skills/research-paper-writing)。

它适合补充 Nature Skills 的期刊导向写法：先固定 paper story，再按章节渐进加载；每段只承担一个 message；写完做 reverse outlining；Abstract/Introduction 的主要 claim 必须回到实验结果；最后进行 adversarial self-review。上一版只列了通用 `scientific-writing`，没有处理同名 Skill 的仓库消歧，这是第二个遗漏。

### 2.3 采用优先级

1. `直接参考`：以文字规则、模板和路由思想为主，不运行第三方脚本。
2. `受限调用`：联网检索、下载、API、Zotero 写操作或外部模型调用，必须显示数据去向和获得用户授权。
3. `不直接嵌入`：第三方可执行脚本不复制到 SR 包；确有需要时，通过适配层调用并固定版本。
4. `许可证隔离`：CC BY-NC 4.0 内容只能作为非商业参考，不进入拟采用 MIT/Apache-2.0 发布的 SR 核心文本。

## 3. SR Skill 总体结构

### 3.1 命名

- 用户可见 ID：`SR-00`、`SR-01`……`SR-68`。
- 实际目录与 frontmatter：Codex Skill 规范只允许小写字母、数字和连字符，因此使用 `sr-00`、`sr-01`……`sr-68`。
- `SR-00` 是总编排器；`SR-01`～`SR-68` 与原文 68 个可执行工作包一一对应。
- 不把 `SR-XX` 设计成 68 套互相复制的长说明。公共定义放在 `SR-00/references/`，叶子 Skill 只保存触发条件、输入、流程、输出和停止条件。

### 3.2 推荐目录

```text
.codex/skills/
├── sr-00/
│   ├── SKILL.md
│   ├── agents/openai.yaml
│   ├── manifest.yaml
│   └── references/
│       ├── lifecycle.md
│       ├── evidence-contract.md
│       ├── human-ai-boundary.md
│       ├── permissions.md
│       ├── handoff-contracts.md
│       └── template-index.md
├── sr-01/
│   ├── SKILL.md
│   └── references/template.md
├── ...
└── sr-68/
    ├── SKILL.md
    └── references/template.md
```

### 3.3 `SR-00` 编排职责

`SR-00` 只完成以下工作，不代替叶子 Skill 做检索、分析、写作或实验：

1. 读取课题目标、当前状态、已有产物和本周可用资源。
2. 找出当前最阻塞认知推进的未知量。
3. 推荐一个 P0 工作包，必要时再推荐一个有依赖关系的 P1 工作包。
4. 冻结输入、完成标准、权限级别和交付路径。
5. 调用对应 `SR-XX`，接收结构化交付物。
6. 执行证据门：来源、数据、版本、反例、适用边界是否齐全。
7. 要求博士生作出接受、修改、暂停或转向决定。
8. 更新认知、工作包状态和下周计划；不得仅以“生成了文件”判定完成。

### 3.4 四级权限

| 级别 | 含义 | 默认处理 |
|---|---|---|
| `L0` | 只读本地材料、推理、生成候选文本 | 可自动执行 |
| `L1` | 访问公开网络、论文数据库、开放 API | 执行前说明检索范围与数据去向 |
| `L2` | 修改本地数据、文稿、Zotero 或运行实验 | 先冻结目标路径、版本和回退方法 |
| `L3` | 对外发送、投稿、邮件、共享敏感数据、高成本实验 | 必须由博士生明确确认；AI 不得代替最终提交 |

## 4. 68 个工作包与 SR Skill 一一对应

说明：每行的“古法流程”表示博士生在没有 AI 时仍应掌握的科研基本功；“人机协作”中，AI 负责提速和暴露遗漏，博士生负责真实性、取舍和结论。典型模板是该工作包的最低可验收载体。

### 4.1 研究问题与选题

| 工作包 | SR Skill（组合来源） | 博士生古法工作流程 | 人与 AI 协作推进 | 典型模板 |
|---|---|---|---|---|
| 场景与需求定义 | `SR-01`（`N-PROP`、`ARS-DR`、`K-SW`） | 访谈需求方 → 手记原话与来源 → 区分科学问题/工程要求 → 让需求方确认 | AI 整理访谈、找矛盾和缺项；博士生核对原意、约束和敏感信息 | 场景卡：使用者 / 时机 / 输入 / 输出 / 性能约束 / 来源 / 待确认 |
| 问题形式化 | `SR-02`（`K-HG`、`N-PROP`） | 写一句话问题 → 定义变量与单位 → 写映射、目标、约束和指标 → 用样例手算 | AI 提供候选形式化和维度检查；博士生确认物理/领域含义与可测量性 | 形式化表：符号 / 类型 / 单位 / 已知性 / 范围 / 来源 / 评价指标 |
| 研究边界收敛 | `SR-03`（`K-HG`、`ARS-DR`） | 罗列全部变量 → 固定大部分因素 → 保留主要矛盾 → 与导师确认不做什么 | AI 生成范围反例和隐含变量；博士生根据毕业主线与资源裁剪 | 边界卡：范围内 / 范围外 / 固定量 / 变化量 / 删减理由 / 重开条件 |

## 5. 每个 `SR-XX` 的统一使用说明

### 5.1 开始前：先做 15～30 分钟“古法首轮”

不要把一片空白直接交给 AI。博士生先独立写出：

1. 当前要回答的一个问题。
2. 已经掌握的事实和对应来源。
3. 自己当前的判断或假设。
4. 最担心出错的地方。
5. 本工作包的可检查交付物和停止条件。

这份首轮笔记是 `human_baseline`。AI 输出必须与它并列保存，便于发现 AI 是否改变了问题、偷换了概念或让博士生在没有证据时被动接受流畅答案。

### 5.4 执行中的人与 AI 分工

| 环节 | AI 适合负责 | 博士生必须负责 |
|---|---|---|
| 搜索 | 扩展关键词、跨库检索、去重、候选排序 | 确定纳排标准，核对关键原文与来源真实性 |
| 阅读 | 提取结构、证据、页码候选、疑点 | 复核原文，区分作者 claim、直接证据和自己的解释 |
| 假设 | 生成竞争假设、反例、可区分预测 | 选择科学上有意义且可承担的假设 |
| 实验 | 生成实验卡、检查混杂、写运行脚本、汇总日志 | 批准设计与预算，执行高风险/实体实验，处理异常 |
| 统计 | 计算、假设检查、效应量、区间、作图 | 确认 estimand、样本单位、独立性和实际意义 |
| 写作 | 提纲、草稿、压缩、术语一致性、claim-evidence 审计 | 对事实、数字、引用、署名和最终结论负责 |
| 项目推进 | 依赖分析、产物盘点、提醒、候选计划 | 承诺日程、协调真人、分配资源、决定停止或转向 |

### 5.5 完成时的证据门

工作包只有同时满足下列条件才可关闭：

- 问题和完成标准没有被悄悄替换。
- 所有关键来源可定位到 DOI、URL、文件版本、页码、图表或原始数据。
- AI 生成的引用、数字和结论已经由博士生抽检；核心 claim 必须全检。
- 事实、分析、猜测和计划分开记录。
- 明确写出当前结论的适用边界和至少一个反例/失败案例。
- 交付物可由另一名组员打开、检查或复现。
- 博士生明确作出接受、修改、暂停或转向决定。

## 6. `SR-00` 每周科研推进方式

```text
课题总目标
  ↓
读取上周交付与未决问题（SR-59）
  ↓
找出最阻塞的未知量
  ↓
选择一个 P0 工作包，必要时选择一个依赖型 P1（SR-60 / SR-66）
  ↓
博士生先完成古法首轮
  ↓
调用对应 SR-XX，冻结工作契约
  ↓
AI 辅助 + 博士生执行/核验
  ↓
证据门与人工决定（SR-48 / SR-61）
  ↓
形成组会材料、下周计划和可接续归档（SR-58 / SR-68）
```

推荐每周只组合以下三种关系之一：

- `输入 → 输出`：例如 `SR-09 单篇深读 → SR-16 核心假设`。
- `主证据 → 辅证据`：例如 `SR-34 主对比 → SR-35 消融`。
- `发现问题 → 关闭问题`：例如 `SR-43 Failure case → SR-46 最小诊断实验`。

禁止让 `SR-00` 为了“流程完整”一次启动八个方面。博士生科研的周单位应是一次可追踪的认知更新，而不是 AI 生成文件的数量。

## 8. 实施路线

### Phase 1：最小可用骨架

先实现 `SR-00` 和 12 个高频叶子 Skill：`SR-07`、`SR-09`、`SR-16`、`SR-20`、`SR-25`、`SR-31`、`SR-32`、`SR-34`、`SR-41`、`SR-48`、`SR-49`、`SR-66`。这些 Skill 覆盖文献、假设、实验、分析、结论和周计划的最短闭环。

验收标准：每个 Skill 能生成工作契约、目标模板和关闭记录；`SR-00` 能基于当前未知量选择一个 P0；不会自动越过 L1～L3 权限。

### Phase 2：补齐 68 个叶子 Skill

按本文映射补齐剩余 Skill。公共证据契约、权限和关闭模板只保留一份；各叶子 Skill 只写本工作包真正不同的步骤、输入和停止条件。

验收标准：68 个工作包无缺项、无重复 ID；所有描述可被正确触发；每个典型请求只能路由到一个主 Skill，必要时声明一个辅助 Skill。

### Phase 3：适配第三方 Skill

新增适配器而非复制第三方脚本：

- Nature Skills：优先接入 `nature-paper-card`、`nature-experiment-log`、`nature-writing`、`nature-reviewer`、`nature-statistics`。
- K-Dense：优先接入 `hypothesis-generation`、`experimental-design`、`exploratory-data-analysis`、`statistical-analysis`。
- Academic Research Skills：仅接入阶段/交接思想；在许可证边界确认前不打包其正文。
- Research Paper Writing：吸收 reverse outline 与 claim-evidence 工作法；保留来源和许可证说明。

验收标准：每个适配器记录上游仓库、commit、许可证、调用权限、输入输出和失败回退；第三方更新不会静默改变 SR 的路由或权限。

### Phase 4：与 Scienceresearch 工作台集成

将 `skill_id`、工作契约、交付物、证据、人工决定、状态和下一步接入现有工作包/成效卡数据模型。组会页从关闭记录生成，不从聊天摘要生成。

验收标准：网页可以从课题进入工作包、查看人机分工与证据、验收交付物、记录人工决定，并在刷新/重启后保持一致。

## 9. 安全扫描记录

扫描器：Cisco AI Skill Scanner `2.0.13`。使用本地 `static_analyzer`、`bytecode`、`pipeline`、`behavioral_analyzer`、`trigger_analyzer`；未启用 LLM、VirusTotal、AI Defense 或其他会上传内容的分析器。扫描对象是 2026-09-08 获取的完整 Skill 目录，不只扫描 `SKILL.md`。模型价格表网络读取曾超时，扫描器使用本地备份；五类本地分析器均完成。

### 9.1 Nature Skills

- 未检出已知问题：`nature-experiment-log`、`nature-literature-pipeline`。
- 只有 Info/Low：`nature-data`、`nature-paper-card`、`nature-paper2ppt`、`nature-polishing`、`nature-reader`、`nature-ref-verifier`、`nature-reviewer`、`nature-statistics`、`nature-writing`、`nature-shared`。主要是 Skill frontmatter 未单独声明许可证；仓库根许可证为 Apache-2.0。
- Medium：`nature-citation` 存在未声明网络使用；`nature-proposal-writer` 有一个 Markdown/YAML 文件类型不匹配；`nature-figure` 有网络调用、未固定依赖、不可分析二进制和一项 Unicode 隐写规则命中。科研绘图优先使用本地 Python/R 路径，OpenRouter 图像路径需单独授权，示例二进制不进入 SR 包。
- High：`nature-response` 的一致性脚本有两个 `while True` 规则命中，接入前需人工确认退出条件。
- Critical：`nature-academic-search` 有 5 Critical，涉及环境变量/网络组合和路径拼接；`nature-downloader` 有 7 Critical、13 High，涉及凭据、网络、child process、文件读写和浏览器下载。二者只能作为隔离、版本固定的受限适配器，不能成为 `SR-00` 的默认自动路径。

### 9.2 Academic Research Skills

`academic-pipeline`、`academic-paper`、`academic-paper-reviewer`、`deep-research` 均仅检出一项 Info：frontmatter 未单独声明许可证。此结果应表述为“未发现已知安全问题”，不是“已验证安全”。仓库许可证为 CC BY-NC 4.0，SR 发布和商业使用前需要单独做许可证判断。

### 9.3 Research Paper Writing

`research-paper-writing` 仅检出一项 Info：frontmatter 未单独声明许可证；仓库根许可证为 MIT。仍需保留来源归属，并注意其 README 说明核心方法论主要整理自彭思达老师公开笔记。

## 10. 最终建议

1. 将 `nature-skills` 纳入 SR 的主要流程参考，尤其是渐进加载、共享参考层、科研产物导向和中文科研使用体验。
2. 将 `academic-research-skills` 作为编排与质量门参考，不作为可直接复制到宽松许可证项目的内容源。
3. 将 `research-paper-writing` 作为论文段落与章节微流程参考，弥补通用写作 Skill 对 paper story、reverse outline 和 reviewer first impression 的不足。
4. SR 的核心竞争力不应是再次打包几十个第三方 Skill，而应是把 68 个工作包、证据契约、人工决定和每周组会闭环连成一条可追踪科研主线。
5. 实施时先做 `SR-00 + 12 个高频 Skill`，用真实课题运行两到四周后再扩到 68 个，避免在没有使用证据前制造大量重复维护面。
