# AI4SCIENCE

推荐使用同一版本组合中的 `myagent/scripts/create_project.py` 建立项目，选择research或software并明确初始要求。默认预览，显式--write才创建，目标存在则拒绝覆盖。不要直接复制整棵模板或使用旧发行包替代本版入口。

当前候选已验证脚本型科研和软件项目；网页、服务、训练等能力需要另行适配与验证，不因有模板目录就声明可用。

本仓是科研项目模板，提供可选工程结构、最小记录规则和内部检查工具。目录和模板不代表已完成算法、产品或性能实验；尚无可据此宣称的科研结果或用户验收。

## 阅读入口

从[四文档导航](projectname/project/docs/README.md)开始，依次阅读项目技术说明、使用指南、结果说明与适用范围。它们面向审阅和使用者；机器资料保留在工程源文件及原始证据，不写入正文。

## 建立真实项目

1. 明确用户要解决的问题、已有材料、完成条件和授权范围。
2. 按实际需要选择算法/数据处理或网页/服务/存储等能力目录；未选能力不创建，不复制整棵模板填空。
3. 配置唯一项目标识、工程/成效位置与已需运行入口，保留可复现输入和真实限制。
4. 用真实实现及已有结果填写四文档；没有实现或结果时明确写未建立，不复制模板维护记录、历史产物或演示数字。
5. 在同一已批准目标内持续完成必要修复、恢复、剩余单元及复核；只有范围、资源或权限变化才暂停相关分支。

## 文件与记录

代码、配置、测试和原始运行留在projectname/project；实际专题成果归achieve并引用来源。两类新日记录只有用户需求与重要进展；不默认产成果卡、工作契约、交接、监督、变更、反思、质量或成本稿。范围决定写需求，结果由真实成果承载，接续由run状态承载。原始证据、独立评审内容、具名决定及旧原件保留，精简不取消必要检查。

科研派生项目的重要进度按group-meeting/1.0讲清研究问题、实际工作、结果、解释、局限与下一步；普通软件项目按需求与用户功能进度说明，不强加科研字段。没有实际变化不建日志，不把内部检查成绩当进度。
