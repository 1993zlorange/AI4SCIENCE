# 工程运行日志模板

## 1. 用途与边界

本模板定义训练、评估、预测等工程运行的结构化日志契约。它约束运行时 `Reporter` 由 tracking adapter 写入的事件，不是项目管理日志、科研成果卡或人工实验记录。

每个运行使用唯一 `run_id`，运行日志写入：

```text
var/runs/<YYYYMMDD>/<run_id>/logs/events.jsonl
```

`events.jsonl` 使用 UTF-8 编码；每行只能包含一个完整 JSON 对象。可选的人类可读日志与该文件同目录保存，但不替代它。指标写入 `metrics/`，模型、表格和预测写入 `artifacts/`，不得把大数组或原始样本塞入日志。

## 2. 每条事件的必填字段

| 字段 | 类型 | 填写规则 | 示例 |
|---|---|---|---|
| `timestamp` | string | 含时区的 ISO 8601 时间；有可用精度时保留毫秒 | `2026-09-13T10:52:31.247+08:00` |
| `level` | string | 标准级别：`DEBUG`、`INFO`、`WARNING`、`ERROR`、`CRITICAL` | `INFO` |
| `service` | string | 稳定的应用、模块或 adapter 名称 | `ai_project.training` |
| `run_id` | string | 与同次运行的 manifest、指标和产物完全一致 | `20260913-1049-a1b2c3` |
| `event` | string | 稳定的 `lowercase_underscore` 事件名 | `training_started` |

## 3. 可选字段

| 字段 | 类型 | 使用规则 |
|---|---|---|
| `message` | string | 简短、稳定的人类可读说明；调用方不得解析它获取业务数据。 |
| `fields` | object | 标量或短字符串上下文，例如步骤号、耗时、数据分区和配置版本；不得放入大数组、原始样本、完整 manifest 或绝对路径。 |
| `error` | object | 仅错误事件使用，包含安全的 `type`、`message`、`code`（如有）和受控诊断信息；不得含密钥、令牌、连接串或内部绝对路径。 |
| `status` | string | 仅终态事件使用：`succeeded`、`failed`、`cancelled` 或 `interrupted`。 |

## 4. 事件示例

```json
{"timestamp":"YYYY-MM-DDThh:mm:ss.sss+08:00","level":"INFO","service":"ai_project.training","run_id":"<run_id>","event":"training_started","message":"训练开始","fields":{"algorithm_id":"<algorithm_id>","data_version":"<data_version>"}}
{"timestamp":"YYYY-MM-DDThh:mm:ss.sss+08:00","level":"INFO","service":"ai_project.training","run_id":"<run_id>","event":"training_finished","message":"训练结束","fields":{"duration_seconds":0.0},"status":"succeeded"}
```

## 5. 端口职责与写入规则

- `Reporter`：只负责上报并由 `tracking` adapter 写入结构化事件；算法通过注入的端口调用它，不直接打开日志文件。
- `ArtifactWriter`：只负责由 `artifacts` adapter 写入 manifest、检查点和受控产物；产物必须可追溯至同一 `run_id`。
- CLI 人类日志写入 `stderr`，`--json` 最终结果写入 `stdout`；不得用日志文本承载机器可解析结果。
- 失败、取消和中断必须写入真实终态事件；不得把未完成运行标为成功。
- 测试使用内存实现或临时目录，不写入 `var/runs/`。

## 6. 实现与验收清单

| 检查项 | 验收标准 |
|---|---|
| 路径 | 每个事件文件位于唯一的 `run_id` 目录，且不提交 Git。 |
| 格式 | 每一行可独立解析为 JSON，全部必填字段存在且类型正确。 |
| 一致性 | 事件、manifest、指标和产物使用同一 `run_id`。 |
| 安全 | 不含密钥、敏感原始数据、不必要绝对路径或未脱敏异常内容。 |
| 终态 | 成功、失败、取消或中断之一被如实记录。 |
| 测试 | Reporter 与 ArtifactWriter 实现通过共享 contract tests；文件适配器在临时目录完成集成验证。 |
