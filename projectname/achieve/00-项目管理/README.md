# 00-项目管理

本目录保存项目管理与治理证据，不保存科研实施代码、数据、实验运行产物或工作流成果卡。科研实施材料归属 `projectname/project`；科研成果、交接书和正式表达材料归属 `projectname/achieve` 下对应的成效目录。

## 目录结构与用途

当前已建子目录如下。

| 目录 | 用途 |
|---|---|
| `requirements/` | 用户需求、范围、验收标准、约束与授权状态记录。 |
| `supervision/` | 项目监理记录，包括操作范围、权限、风险、验证和停止条件。 |
| `logs/` | 事实性项目日志，记录实际动作、影响、证据、限制和下一步。 |
| `dailylogs/` | 按文件名日期汇总项目日志形成的日报，命名为 `YYYYMMDD-摘要-日报.md`。 |
| `reflections/` | 用户指出的问题、确认缺陷或重复问题的反思记录。 |
| `changes/` | 变更原因、影响、兼容性、验证和回滚信息。 |
| `quality/` | 质量门禁、检查范围、命令或方法、结果和未执行项。 |
| `costs/` | 人工、计算、外部服务和运行成本的事实记录。 |
| `skills/` | 项目级 Skill 的提案、试点、晋升与回滚证据。 |
| `templates/` | 已登记文档类型的中文结构化空白模板及其登记记录。 |
| `tools/` | 项目治理脚本工具的日期化 API 说明。 |

`skills/` 已在首个项目级 Skill 产生技能提案时创建；后续只保存具体的 Skill 治理产物，不保存全局安装副本。

## 命名方式

管理类文档采用以下格式：

```text
YYYYMMDD-内容简述-文档类型.扩展名
```

示例：`20260913-十二工作流交接目录-需求记录.md`。

同日产生多份文档时，使用不同且明确的“内容简述”区分；不得通过覆盖旧文件解决重名。文档正文使用中文，并如实区分已执行事实、推测和未执行项。

`README.md` 是固定目录入口文件，属于固定技术文件名例外，因此不采用日期前缀；该例外不免除其目录归属和维护要求。

## 使用边界

- 新目录仅在其首个具体产物已经明确、并已在需求记录中登记责任、用途和生命周期时创建。
- 科研成果卡和工作流交接书写入 `achieve` 下对应的八类成效目录及工作流子目录，不写入本目录。
- 新建或修改的管理记录应同时保留需求、监督、变更、质量、日志和成本证据；涉及实际问题时另建反思记录。
