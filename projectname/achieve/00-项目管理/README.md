# 项目记录入口

本目录只保存真实需要的项目记录，不保存代码、原始实验数据或另一套科研结论。具体类型映射由 `projectname/project/configs/features.yaml` 的 `record_policy` 统一管理，所有路径相对于模板根；生成器从根AGENTS中的 `record_policy_registry` 定位它。

## 同日同类型一个文件

唯一键为项目、Asia/Shanghai记录日和规范记录类型；任务、Agent、阶段、目录与格式不增加拆分维度。需求/监督/日志/反思/变更/质量/成本各沿既有目录，同义名称先归一。名称固定为 `YYYYMMDD-固定主体-规范类型.md`，例如 `logs/YYYYMMDD-科研进度-日志.md`。没有真实条目就不建文件；存在则追加，不换任务名或运行ID另建。

每条有稳定ID、事件与尝试身份、实际记录/发生时间、需求或研究要点、内容、证据和独立状态。多Agent由一个写入者汇总；冲突时重读合并，临时写入后原子替换。修订追加并保留原文，不回填日期。跨日新进展进入实际记录日，关联旧条目。

## 用途边界

- 科研日志只含研究要点及出处、性能问题、条件/指标、实际结果、科研影响和下一步。工程检查、格式/哈希核对、角色流转不进入科研日报。
- 必要需求、变更、质量、成本和反思按真实事件触发；不每次工作生成一套，也不每日补齐类型。
- 新科研成果卡、工作契约、交接书和人工决定各类型统一到 `08-项目推进与下一步计划` 的日文件，每叶任务/真实交接仍为独立条目；本目录不复制其正文。
- `dailylogs/` 等旧汇总属于只读历史，不为同一用途再维护第二份人工日报。HTML/PDF导出从母版生成并声明来源，不独立追加。
- 生效日前旧文件原位只读，已有重复不冒称已归一；新历史例外需在策略显式登记。正式报告、签署原件、原始run、源码和固定输入保留各自身份。

新目录只在首个产物明确后建立；本入口不要求补空目录或迁移历史。规则全文以根级AGENTS为准。
