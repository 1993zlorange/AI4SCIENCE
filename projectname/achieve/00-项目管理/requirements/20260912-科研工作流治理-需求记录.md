# 科研工作流治理需求记录

## 1. 来源与背景

- 用户原意摘要：依据既有科研流程、四 Agent 工作流和科研项目负责人使用规则，优化模板根级 `AGENTS.md`，使新项目可直接组织科研工作。
- 来源轮次/证据：当前用户请求及其既有全局命名、中文模板、日志与反思治理要求。
- 当前问题与影响：原根级文件只有通用项目治理，没有科研十二工作流、实际 Agent 路由、负责人运行方式，也没有把实施目录和成效目录映射到模板现有结构。

## 2. 原子需求

| 需求 ID | 要求 | 优先级 | 范围 | 非目标 | 验收标准 | 状态 |
|---|---|---|---|---|---|---|
| REQ-01 | 在模板根级规则中写入科研十二工作流及依赖顺序 | P0 | 根级科研治理 | 不修改专业 Agent 自身职责 | 十二个工作流均有阶段、主责、目标、输入和交接目录 | 已实现 |
| REQ-02 | 写明实际科研 Agent 名称及调用方式 | P0 | 科研负责人和四个专业 Agent | 不新增或改名全局 Agent | 五个实际 Agent 可核对，提供只读、编排和专业派发调用结构 | 已实现 |
| REQ-03 | 写明科研项目负责人 RPL-01 至 RPL-04 的运行方式 | P0 | 盘点、阶段判断、建议、派发验收 | 不允许默认只读请求隐式派发 | 默认只读与明确授权编排边界清楚 | 已实现 |
| REQ-04 | 科研实施统一位于 `projectname/project` | P0 | 代码、数据处理、实验、测试和运行证据 | 不移动现有工程目录 | 根级和工程级规则采用一致相对映射 | 已实现 |
| REQ-05 | 科研成效统一位于 `projectname/achieve` | P0 | 成果卡、交接书、报告、论文和项目管理记录 | 不批量创建空成效目录 | 八类成效目录及十二个交接目录有明确规则 | 已实现 |
| REQ-06 | 根级规则与工程 `AGENTS.md` 有效配合 | P0 | 治理优先级、文件归属和冲突处理 | 不重写工程编码细则 | 工程级重复监理配置已移除并显式回读根级规则 | 已实现 |
