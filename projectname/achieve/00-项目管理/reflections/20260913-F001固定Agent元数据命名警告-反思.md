# F001 固定 Agent 元数据命名警告反思

## 1. 目标与事实

- 关联需求/问题 ID：ISSUE-F001-AGENT-METADATA-NAMING。
- 预期结果：F001 对项目内日期化文档执行命名检查，同时排除工具链要求固定名称的元数据文件。
- 实际结果：运行 F001 时，`.codex/skills/pr-ps-09-daily-log-summary/agents/openai.yaml` 产生“未采用日期化名称”警告。
- 证据：本批质量门禁命令输出 `ERROR=0 WARNING=1`；F001 源码的固定名称集合未列出该 Agent 元数据文件或其目录规则。

| 偏差 | 根因类别 | 已证事实 | 推测 | 影响 |

| 合法固定 Agent 元数据被日期化命名检查警告 | 规则/实现 | F001 扫描 `.yaml` 文件，固定名称例外仅覆盖一组顶层文件名，未排除 `agents/openai.yaml` | 其他 Skill 元数据目录可能产生同类噪声 | 门禁警告不再只代表需人工处置的命名风险，降低信噪比 |

## 3. 可复用规律

- 适用范围：所有同时包含日期化业务文档和固定工具链元数据的项目级 Skill 目录。
- 不适用范围：真正新建、非固定入口且不在 `docs/`、`examples/` 等受控目录的业务文档。
- 同类历史证据：本批首次发现；尚未达到自动演化阈值。
- 与现有规则的关系：根级 AGENTS 已允许固定技术入口稳定命名；F001 的排除规则应与此保持一致。
