# 治理审计整改反思

## 1. 触发与事实

- 触发类型：用户明确要求依据治理对齐审计优化。
- 关联审计：`../supervision/20260912-AI4SCIENCE治理要求对齐审计-对齐审计.md`
- 事实：原规则能够生成治理文档，但没有功能身份注册表、全量只读校验器、日志独立原因/影响字段、Skill 随附模板和晋升证据登记。

## 2. 根因与影响

- 根因分类：规则与验证设计。
- 为什么发生：治理要求分散在 AGENTS、Skill、模板和工具包中，缺少统一元数据和固定的证据闭环。
- 实际影响：新功能、日志影响和项目 Skill 晋升容易依赖人工记忆，审计只能发现问题，不能稳定复核。
- 受影响下游：项目启动、工程实现、科研交接、质量门、Skill 演化和全局安装决策。

## 3. 最小改进

| 改进对象 | 修改内容 | 责任人 | 验证 |
|---|---|---|---|
| 根级治理 | 增加功能注册表、晋升登记、固定技术文档例外和日志影响字段 | 项目监理 | 读取 AGENTS.md；运行两个校验器 |
| 工程工具 | 增加 F001/F002 只读审查脚本及中文 API 说明 | 工程师 | `py_compile`、脚本试运行 |
| 文档型 Skill | 为工具包 5 个本地 Skill 及 SR 路由包补齐随附中文模板 | Skill 维护人 | 路径和链接检查 |

## 4. 边界与后续

- 未迁移、删除或重命名历史文件；未执行全局 Skill 安装。
- 功能注册表当前为空，表示模板尚无已实现功能，不代表功能覆盖率已通过。
- 14 天或累计 3 次同类问题后复核误报、漏报和维护成本，再决定是否升级校验器。
